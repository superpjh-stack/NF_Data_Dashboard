# 니즈푸드 데이터 대시보드

고려솔더 데이터 대시보드의 탐색·분석 방식을 참고한 파란색 테마의 니즈푸드 로컬 대시보드입니다. 제공받은 니즈푸드 데이터 폴더를 읽어 업무별 목록, 레시피 구성·배합 분포, 생산·수불 대사와 데이터 품질을 보여줍니다.

## 실행

`Start_Dashboard.command`를 더블클릭하거나 터미널에서 실행한 뒤 **http://127.0.0.1:8770** 을 엽니다. 터미널을 유지하며, 종료하려면 Control+C를 누릅니다. 이미 실행 중이면 주소를 안내합니다.

```sh
./Start_Dashboard.command
```

최초 실행 때 Python 가상환경에 `openpyxl`, `pyxlsb`를 설치합니다. Python 3.10 이상이 필요합니다. 현재 환경은 설치와 전체 데이터 처리가 완료되어 있습니다.

원본이 변경되었을 때:

```sh
./Refresh_Data.command
```

다른 원본 폴더를 지정할 때:

```sh
./Refresh_Data.command --source '/절대경로/니즈푸드 데이터'
```

새 DB를 완성한 뒤 원자적으로 교체하므로 재처리가 실패하면 기존 분석 데이터를 유지합니다. 처리 중에는 이전 스냅샷을 조회할 수 있습니다. 성공 후 브라우저를 새로고침하세요. 같은 폴더에서 새로고침을 동시에 여러 번 실행하지 마세요.

## 분석 기준과 한계

- 원본은 수정하지 않습니다. 외부 API, 클라우드 업로드, CDN, 외부 폰트 없이 로컬에서 분석합니다. 서버는 `127.0.0.1`에만 바인드합니다. 원격 배포 구성은 아래 Hostinger VPS 항목을 참고하세요.
- SHA256 동일 파일은 대표본만 구조화합니다. 해시가 다른 파일의 실제 업무 중복은 자동 확정하지 않습니다. 임시파일과 복사용 양식은 별도 상태로 둡니다.
- 메뉴·원재료는 Unicode NFC 및 공백만 정리합니다. 브랜드·원산지·규격·고객군 괄호를 임의 병합하지 않습니다. 명칭이 다르면 대사에서 서로 다른 품목입니다.
- 생산일지의 반복 메뉴 분석은 실제 셀 날짜·끼니·메뉴의 원재료 집합을 비교합니다. 같은 메뉴를 5회 이상 기록한 경우만 전체 안정성 비율의 분모로 사용합니다. 동일 날짜가 여러 생산 파일에 겹치면 해당 날짜를 구성 분석에서 제외합니다.
- 생산·수불 비교는 두 장부에 실제 날짜가 모두 있는 날만 사용합니다. 단위가 kg이고 수치가 있는 경우에 사용량을 합산합니다. 허용 차이는 ±0.01 kg입니다. 수불에만 있고 사용량이 0인 품목은 활동 없는 재고이므로 한쪽 장부 누락 수에서 제외합니다. 날짜가 여러 파일에 겹치면 비교에서 제외합니다.
- 날짜·단위·수치의 미확인은 0으로 바꾸지 않습니다. 숫자로 저장된 유한값만 통계에 포함합니다. 비교 차이와 IQR 이상값은 검토 후보이며 불량 판정이 아닙니다.
- 분위수는 선형 보간, 표준편차는 표본 기준입니다. 수치 분포는 한 메뉴·한 원재료·한 항목의 집단으로 제한합니다. 선택기는 기록 수 상위 200개 조합을 제공하고, 메뉴 표에서 다른 메뉴도 선택할 수 있습니다.
- Excel 수식을 재계산하지 않고 마지막 저장된 캐시 값을 읽습니다. 캐시가 없으면 수치 미확인으로 표시합니다. 원본 창은 최대 100행씩, 40열까지 실제 저장값을 보여줍니다.
- 추출은 검수·승인과 다릅니다. 메뉴별 원재료 기록은 완성품 생산량이 아닙니다. 센서 스트림과 RAG·벡터 DB는 이 앱에 연결하지 않았습니다.
- 분석은 스냅샷입니다. 원본 상세를 열 때 현재 파일 해시가 바뀌면 경고합니다. 폴더 전체의 추가·삭제를 실시간 감시하지 않으므로 변경 후 새로고침을 실행하세요.

## 검증

```sh
.venv/bin/python -m unittest discover -s tests -v
# 서버가 실행 중인 상태에서 실제 데이터/API 검증
.venv/bin/python tests/verify_snapshot.py
node --check src/static/app.js
```

단위 테스트 24개, 전체 원본 해시 대조, 실제 원본 셀 근거 대조, 로컬 API·검색·필터·CSV·다운로드 검증을 제공합니다. 결과는 `reports/verification.json`에 기록됩니다. 브라우저 자동 접근은 이 세션의 원본 주소 승인에서 거부되어 실제 렌더링과 클릭·반응형 시각 검증은 수행하지 못했습니다.

## 구성

- `src/pipeline.py`: 파일 조사·해시·제목 기반 XLSX/XLSB 추출·원본 근거 저장
- `src/analytics.py`: 읽기 전용 통계·레시피·장부 대사
- `src/server.py`: 로컬 API·원본/CSV 다운로드·시트 조회
- `src/static/`: 한국어 대시보드 화면
- `data/needsfood.sqlite`: 원본 목록과 정형 행 스냅샷(로컬 생성 파일)
- `docs/`: 설계·실행 계획
- `reports/`: 처리·검증 결과(로컬 생성 파일)

현재 앱은 검수 수정, PostgreSQL 적재, OCR, 한글 변환, 실시간 센서 수집, 임베딩을 실행하지 않습니다.


## EDA·ML 검토

직접 열기: **http://127.0.0.1:8770/#eda**

원본 스냅샷을 다시 읽어 EDA만 재생성하려면 `Run_EDA.command`를 실행합니다. 원본이 바뀌었으면 `Refresh_Data.command`를 사용하세요. 보고서 다운로드는 화면의 HTML/JSON 버튼을 사용합니다. 결과 파일은 `reports/eda.json`, `reports/eda-review.html`, 검증 기록은 `reports/eda-verification.json`입니다.

현재 스냅샷의 주요 결과:

- 생산일지 49,294행, 실제 날짜 747일(2023-01-02~2026-08-20). 관측 범위에 기록 없는 월은 12개이며 수요 0으로 간주하지 않습니다.
- 조리계획서 실제 날짜를 명시적으로 연결한 행은 88 / 176,877행(0.05%)입니다. 원본에 날짜가 없다는 뜻이 아니라 현재 파서로 확보한 연결 수준입니다.
- 반복 5회 이상 메뉴 697종 중 원재료 집합이 항상 같은 메뉴는 67종입니다. 구성 차이는 고객군·계절·대체 재료의 정상 차이일 수도 있습니다.
- 같은 메뉴·원재료의 양수 1인량, 20행 이상·관측 5일 이상 집단은 400개입니다. 비교한 19,412행 중 IQR 후보는 913행이고 IQR=0 집단은 245개입니다. 오류·불량의 확정 라벨이 아닙니다.
- 실제 공통 날짜 720일의 생산·수불 비교에서 숫자로 비교 가능한 건은 19,442건, 수량 차이는 2,268건입니다. 한쪽만 있는 기록을 분모에 섞어 불량률로 표시하지 않습니다.

실행한 기준선 검증:

| 항목 | 결과 |
| --- | --- |
| 과거 구간 | 2023-01-02~2026-02-11, 33,267관측 |
| 이후 검증 구간 | 2026-02-12~2026-08-20, 8,775관측 |
| 메뉴·원재료별 과거 중앙값으로 예측한 관측 | 3,879건, 커버리지 44.2% |
| 메뉴·원재료 중앙값 MAE | 2.11 g |
| 메뉴·원재료 중앙값 WAPE | 3.57% |
| 원재료 중앙값 MAE(동일 3,879건) | 3.82 g |
| 원재료 중앙값 WAPE(동일 3,879건) | 6.45% |

**학습형 ML 모델을 학습한 결과가 아닙니다.** 과거 기재값의 통계적 기준선입니다. 긍정적으로 보이는 오차도 전체 검증 관측의 44.2%에 한정됩니다. 승인 배합·고객군·단위를 검수하기 전 자동 확정에 사용하지 않습니다. 메뉴 변경이나 새 메뉴에 대한 성능이 검증된 것도 아닙니다.

먼저 적용할 과제는 레시피 1인량 후보·입력 편차 검토와 규칙 기반 장부 정합성 점검입니다. 수요·발주 예측에는 확정 식수·미래 메뉴 계획·운영 달력·공통 품목 코드·리드타임이 필요합니다. 공정→품질 예측에는 현재 스키마에 없는 LOT·설비 시계열·검사·불량·폐기 라벨의 연결이 선행되어야 합니다.

기준선은 [시간순 분할](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)과 [데이터 누출 방지](https://scikit-learn.org/stable/common_pitfalls.html) 원칙을 적용했습니다. 통계 중앙값은 Python 표준 라이브러리로 계산하며 scikit-learn을 설치하거나 모델을 훈련하지 않았습니다.
